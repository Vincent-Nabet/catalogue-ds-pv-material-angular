# Tokens sans variable native dans Material Design 3 / Angular Material 22

Document pour le design : liste des variables des fichiers `tokens/` qui n'ont **pas de variable native** dans Angular Material 22 (`@angular/material` 22.2.x, variables système `--mat-sys-*`).

Vérifié dans la documentation Angular Material et dans les sources installées (`node_modules/@angular/material/core/tokens/m3`).

Remarques :
- Toutes les variables système Angular Material (`--mat-sys-*`) sont **surchargeables** : en CSS, ou en Sass avec `mat.theme-overrides((...))` (vérifié dans `core/tokens/_system.scss`). Les valeurs de couleur, typographie, forme et opacités d'état du design system peuvent donc être injectées dans les variables existantes. Ce document liste ce qu'on **ne peut pas surcharger, faute de variable native** : il faudra créer des variables CSS custom.
- **Rappel « MD3 Expressive »** : évolution de Material Design 3 publiée par Google en 2025 (styles de texte « emphasized » à graisse renforcée, rayons de coins plus grands, nouveaux composants et animations). Quand ce document dit « MD3 Expressive », cela signifie que la variable n'existe pas dans Angular Material 22.2.x (version installée) : le token du design doit alors être défini en variable CSS custom. Le rattachement des tokens (suffixe `-increased`, `Weight-emphasized`) à Expressive est déduit de leurs noms, il n'est pas indiqué dans les fichiers de tokens.
- Angular Material utilise le préfixe `--mat-sys-*` (et non `--md-sys-*` comme dans la spécification MD3).
- Les 8 fichiers `semantics/*.tokens.json` ont exactement les mêmes variables non applicables. Les valeurs de la colonne « Valeur » sont celles de `light.tokens.json`. Elles changent selon le thème (dark, contrastes, monochrome).
- Les graisses des fichiers de tokens sont des noms, pas des nombres, et ne sont pas utilisables telles quelles en CSS. Correspondance : `Regular` = 400, `Medium` = 500, `SemiBold` = 600. `SemiBold` n'est pas non plus un mot-clé valide du format DTCG (qui attend `semi-bold`).
- « À définir en variable CSS custom » veut dire : la variable restera utilisable dans l'application, mais ne sera pas fournie par Angular Material.

## 3. Variables natives avec une valeur par défaut différente

Ces variables existent dans Angular Material, mais leur valeur par défaut diffère. Elles sont surchargeables : il suffit de les redéfinir avec la valeur du design system.

| Variable | Valeur ici | Valeur Angular Material | Remarque |
|---|---|---|---|
| Radius.Full | `1000px` | `9999px` | Rendu identique en pratique. Surchargeable. |
| Colors.State Layers.*.Opacity-10 | 0.10 (déduit du nom du token, absent du fichier) | `focus` = 0.12, `pressed` = 0.12 | Pas d'état à 0.10 dans Angular Material 22. La spécification MD3 actuelle fixe focus **et** pressed à 0.10. Les opacités 0.08 (hover) et 0.16 (dragged) correspondent. Surcharger `--mat-sys-focus-state-layer-opacity` et `--mat-sys-pressed-state-layer-opacity` à 0.10 pour s'aligner sur le design. |
| Font theme.Static.Weight.Bold | `SemiBold` | `bold-weight` (700 par défaut) | Configurable dans la typographie du thème (`bold-weight`, `medium-weight`, `regular-weight`). À aligner sur 600 si c'est le choix voulu. |
| Typescale.Static.Label Large / Label Medium . Weight-emphasized | `SemiBold` | `--mat-sys-label-large-weight-prominent`, `--mat-sys-label-medium-weight-prominent` (= `bold-weight`, 700 par défaut) | Équivalent existant uniquement pour ces deux styles. Fixer `bold-weight` à 600 (ligne précédente) aligne aussi ces deux variables sur SemiBold. |
